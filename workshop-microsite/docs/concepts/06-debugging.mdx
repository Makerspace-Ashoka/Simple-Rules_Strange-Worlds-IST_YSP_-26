# Debugging

**Debugging** means finding and fixing mistakes in a program.

A mistake in code is often called a **bug**.

A bug does not mean you failed.  
A bug is a clue that the program is not doing what you expected.

---

## Expected vs Actual

Debugging starts with one question:

> What did I expect, and what actually happened?

Example:

```js
let price = 100;
let discount = 20;
let finalPrice = price + discount;
```

Expected result:

```js
80
```

Actual result:

```js
120
```

The program runs, but the answer is wrong.

That tells us there is a bug.

The correct line should be:

```js
let finalPrice = price - discount;
```

---

## Debugging Is Detective Work

Debugging is like solving a mystery.

You do not just guess randomly.

You investigate step by step:

1. Predict what should happen.
2. Run or read the code.
3. Find where the result becomes wrong.
4. Fix one thing.
5. Test again.

Good debugging is calm and careful.

## Common Types of Bugs

### 1. Syntax Bugs

A **syntax bug** happens when the code is written in a way the computer cannot understand.

Example:

```js
if (score > 10) {
  console.log("You win");
```

The code is missing a closing `}`.

Correct version:

```js
if (score > 10) {
  console.log("You win");
}
```

Syntax bugs are often caused by:

- missing brackets
- missing quotation marks
- wrong spelling
- wrong punctuation
- incorrect indentation or structure

---

### 2. Runtime Bugs

A **runtime bug** happens while the program is running.

Example:

```js
let animals = ["rabbit", "fox"];

console.log(animals[2]);
```

This is a problem because the array only has two values:

| Index | Value |
|---|---|
| `0` | `"rabbit"` |
| `1` | `"fox"` |

There is no value at index `2`.

---

### 3. Logic Bugs

A **logic bug** happens when the program runs, but gives the wrong result.

Example:

```js
let price = 100;
let discount = 20;
let finalPrice = price + discount;
```

The program does not crash.

But the logic is wrong because a discount should be subtracted, not added.

Correct version:

```js
let finalPrice = price - discount;
```

Logic bugs can be harder to find because the code may still run.

---

## Tracing Code

**Tracing** means following the code one step at a time.

Example:

```js
let score = 0;
score = score + 5;
score = score * 2;
```

Trace:

| Step | Value of `score` |
|---|---|
| start | `0` |
| after `score + 5` | `5` |
| after `score * 2` | `10` |

Tracing helps you see where a value changes.

If the value becomes wrong, the bug is probably near that step.

---

## Use Checkpoints

One simple way to debug is to print values while the program runs.

```js
console.log("Before update:", score);

score = score + points;

console.log("After update:", score);
```

This helps you see what is happening inside the program.

Checkpoints are useful when you are not sure where the bug is.

---

## Debugging Simulations

Simulations can also have bugs.

Examples:

- a cell changes when it should not
- a fire spreads too quickly
- an animal moves outside the grid
- a value becomes negative
- the simulation freezes
- the display does not match the stored data

When debugging a simulation, check:

1. **state**: is the data correct?
2. **rules**: are the conditions correct?
3. **loops**: are all objects being updated?
4. **arrays**: are the indexes correct?
5. **functions**: is each function doing one clear job?
6. **display**: is the program showing the correct state?

---

## Test Small First

Large simulations are harder to debug.

Start with a small test.

Instead of this:

```js
let grid = createLargeGrid(100, 100);
```

try this first:

```js
let grid = [
  [0, 1, 0],
  [1, 1, 0],
  [0, 0, 1]
];
```

A small grid is easier to check by hand.

Once the small version works, you can scale up.

---

## Key Idea

Debugging means comparing:

```js
expected result
```

with:

```js
actual result
```

Then finding where the difference started.

A good debugging process is:

```js
predict → run → trace → fix → test again
```

```js

```

### Challenge Card 4: Debug a Loop

This loop is supposed to print numbers from `0` to `4`.

```js
for (let i = 0; i <= 5; i++) {
  console.log(i);
}
```

Answer:

1. What numbers does it actually print?
2. Why is that wrong?
3. What should the condition be?

---

### Challenge Card 5: Debug a Simulation Rule

Imagine this rule for a fire simulation:

```js
if (cellState === "tree") {
  cellState = "fire";
}
```

Problem:

Every tree becomes fire immediately.

Answer:

1. Why is this rule too simple?
2. What extra condition should we check?
3. How could we make the rule more realistic?

Hint:

```js
if (cellState === "tree" && hasBurningNeighbor) {
  cellState = "fire";
}
```

### Challenge Card 6: Make a Debugging Checklist

3. Are the loops visiting every object?
4. Are the array indexes correct?
5. Are the functions returning the right values?
6. Is the display showing the actual data?
